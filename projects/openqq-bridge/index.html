OpenQQ Bridge

项目简介

OpenQQ Bridge 是用于 SeaDice 与 OpenQQ 身份兼容的数据桥接工具。 用于解决 OpenQQ 平台身份变化后， 原有角色卡、属性数据以及日志数据无法直接读取的问题。 支持旧 QQ 数据绑定到当前 OpenQQ 身份， 实现数据兼容读取。

本版支持：

  • 多 SeaDice 实例分别配置 Bridge 端口。
  • 在 SeaDice 插件配置页面填写发件邮箱、SMTP 授权码、SMTP 服务器和端口。
  • .旧QQ邮箱测试：向配置中的发件邮箱发送测试邮件。
  • .旧QQ绑定 <旧QQ> <旧群>：自动向 <旧QQ>@qq.com 发送 6 位验证码。
  • .旧QQ验证码 <验证码>：验证成功后才执行数据迁移。 验证码 5 分钟有效，最多错误 5 次。
  • .旧QQ+旧群已绑定其他 OpenQQ 身份时拒绝再次绑定。

v3.0 新增：增量同步

绑定成功后会 自动开启 定时同步（每 10 分钟一次），不再只是一次性复制。

  • log：双向增量，只追加新条目，不改已有内容。
  • 角色卡：旧QQ → OpenQQ，只增不改，已有的按 id 跳过。
  • PC 数据：OpenQQ → 旧QQ 单向回写，只有 OpenQQ 那边更新时才覆盖， 覆盖前自动备份。

相关指令：

  • .旧QQ同步状态：查看是否开启、间隔、上次跑的时间和结果。
  • .旧QQ立刻同步：马上跑一次，不用等 10 分钟。
  • .旧QQ同步开关 开/关：开启或关闭本群的自动同步。

注意：增量同步无法处理删除——旧群里删掉一条消息，另一边不会跟着删。 并且要求旧群数据仍在同一个海豹库里（桥只读数据库文件，不连服务器）。

v3.0 修复

修复了迁移后角色卡面板显示为空的问题。之前版本会清空"指向他人角色卡"的绑定， 但海豹允许同群共享角色卡，绑定被清空后面板就没东西显示了。 v3.0 改为保留原绑定。数据本身一直没有丢失。

v3.0 修复：兼容 GBK 编码的历史数据

旧版海豹在某些 Windows 环境下，会把中文按 GBK 编码写进数据库。 桥读取时默认按严格 UTF-8 解码，遇到这种数据会直接报错： 

sqlite3.OperationalError: Could not decode to UTF-8
column 'name' with text 'Bryana Marist (?????).st ...'

表现为绑定直接失败、返回 500。现在所有数据库连接都改用了容错解码， 顺序是 UTF-8 → GB18030 → GBK → Big5 → latin-1，最后才做字符替换。 像「Bryana Marist (测试角色).st 力量65str65...」这种角色名， 现在能完整读出，中文和属性数值都不会丢。

影响范围：绑定、角色查询、增量同步全部覆盖， 不再因为个别历史数据卡死整个流程。

使用方式： 双击启动openqq.exe，然后保持运行，不能关闭

在目标QQ 群执行： 如 .旧QQ绑定 2522629086 1081354778，也就是格式是： .旧QQ绑定 <本账号QQ><本QQ群账号>，后bot会朝你使用账号的QQ号@qq.com发送验证码邮件，输入。旧QQ验证码+6位数字的验证码后可绑定。再次绑定该群号和QQ账号会失败，仅限单次数绑定。QQ号+群号可用于多群进行绑定查询log。

绑定完成后再执行： .st或者。pc或者。log，先前的log可通过log get+名字取出。

下载

直接下载 Github Release GitHub 仓库

如果下载后无法打开， 或者打开后立即关闭， 请检查 Windows 安全中心和防火墙是否允许该软件运行。 大概率是被防火墙拦截。

注意： - 插件配置中的“SMTP授权码”不是邮箱登录密码。 - QQ邮箱通常使用 smtp.qq.com:465，并使用 SMTP 授权码。 - 测试邮件会发送到你填写的“发件邮箱”本身。 - bridge_port.txt 与 EXE 放在同步桥目录中；EXE 默认读取其中的端口。 - email_config.json 仅作为兼容/手工启动备用配置，本版正常使用时由 SeaDice 插件配置向 Bridge 临时下发邮箱配置。

不要在干净备份上直接测试 .st；干净备份里的角色仍属于旧 QQ，OpenQQ 官 bot 不会自动显示它。

TIPS：因为文件只读取海豹的data和datalog的db文件，所以有的角色卡可能会在转换以后出现丢失情况，比如出现空角色卡，或者log绑定失败，大部分是因为数据库出现了问题，可用原始备份的data和datalog的db文件进行替换再删除相应的后缀为wal和shm的文件，海豹再度启动会自动生成相应的wal和shm干净文件。data文件会在数据转换前进行备份，后缀是beforexxxx

如十分必要可以来找骰主尝试找回数据。把data和datalog整理读取后可以得到对应的角色卡文件，只要存在过。

这版插件是AI写的代码，不能保证不会出现其他的bug，除此以外，尚未验证过该插件同步的log数据是否能继续记录日志。
